# 课题一成果报告

选题：一，扩展能力插件化框架。成果类型：代码。提交人：刘健（95shisihan）。更新日期：2026-09-12。

## 1. 问题与方案

原有扩展注册分散于不同模块，多数依赖编译期注册，新增检索后端还需修改核心工厂。社区扩展因此与主仓构建和发版耦合。

采用 Manifest 描述插件身份、类型、宿主版本范围、协议版本、配置 Schema 和权限；使用类型化 gRPC 作为公开边界。外部插件独立运行，内置实现通过注册回调进入同一个 Manager。该方案增加进程通信和生命周期管理成本，但能够支持独立交付、跨语言开发和操作系统级隔离。完整方案比较见 [ADR](../../plugin/ADR-0001-out-of-process-plugin-runtime.md)。

## 3. 四项验收与证据

### 3.1 主仓外独立插件完整同步：Windows 已通过

本地 `WeKnora-LocalDirectory-Plugin` 拥有独立 Git 历史，通过全新 Python 环境、随仓库 Proto 与 SDK 构建本机 EXE ZIP，不读取主仓源码。使用宿主正常管理员 API 安装启用。安装与同步期间，宿主源码状态及 EXE 哈希前后不变。

首次新增两篇文档，两篇解析、摘要完成，混合检索及纯向量检索均召回核验文本。这覆盖同步、解析、Embedding、索引和检索，不只是插件 Fetch 或任务入队。

[完整报告及结构化原始记录](../acceptance/windows-independent-plugin-2026-09-11.md)。独立插件源码和安装包已归档到主仓库 `plugins/submission/`，不发布远端仓库；当前主要证据为应用 API 验收，没有完整逐项点击视频。

### 3.2 禁网并记录拒绝：具有 WFP 权限的 Windows 已通过

Manifest 声明 `outbound: false` 后，由 Windows 原生受限进程执行隔离；stdio gRPC 保持宿主与插件通信。父子进程公网 IPv4/IPv6 TCP 连接被系统拒绝。管理员验收捕获四条真实 WFP 拒绝事件，另一个宿主生产运行时集成测试输出两条带插件 ID、地址、端口、协议的 `plugin.network_denied` 日志。

普通权限进程可能无法订阅 WFP。已有证据不能推导为普通部署自动具备审计权限，也不代表每次 UDP 或 loopback 尝试都有日志。Linux AppArmor 实机审计仍待执行。

[禁网报告与原始日志](../acceptance/windows-network-audit-2026-09-11.md)。
