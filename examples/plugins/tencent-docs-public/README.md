# 腾讯文档公开链接导入 0.2.0

这是可导入正文的数据源插件，沿用 `dev.example.tencent-docs-public` 和原连接器类型，兼容已有 `settings.url` 配置。

## 使用

1. 在设置 → 插件管理中确认版本 0.2.0 并启用，批准 `GET docs.qq.com`。版本变化会使旧授权失效，需要重新确认。
2. 在知识库添加数据源，选择「腾讯文档公开链接导入」。
3. 填入具体的 `https://docs.qq.com/doc/文档ID` 链接，可用逗号或换行填写 1～20 个；文档须允许任何人查看。
4. 点击测试连接：必须成功解码非空正文才通过。官网首页、登录页和空文档不会被当作成功。
5. 进入选择范围，勾选显示真实标题的文档，然后保存同步策略并立即同步。
6. 查看知识库中的正文。未修改时再次同步应跳过；修改正文或标题后同步应更新原文档。

## 支持范围

- 支持普通腾讯在线文字文档 `/doc/` 的完整非分块快照；提取纯文本，保留段落、列表文字。
- 支持资源选择、全量同步、内容和标题 SHA-256 指纹增量更新。仅处理所填链接，不遍历文件夹或子文档。
- 不支持表格、幻灯片、智能文档、图片 OCR、附件正文或复杂版式还原。分块长文档、未知编码、空文档会明确报错，避免将不完整正文作为成功导入。
- 文档被删除或撤销权限时同步失败，保留已导入内容；不会据一次访问失败自动删除知识库文档。
- 修改资源范围后需要执行全量同步；不自动清理取消勾选的旧文档。

## 网络与升级

插件禁止直接联网，仅通过宿主受控 HTTP 发送 GET，请求域名仍只有 docs.qq.com，超时 20 秒、响应 2 MiB。
腾讯文档正文端点要求同源来源标头，因此宿主新增严格限制：Referer 只能是目标 HTTPS 同源根地址，不能包含文档路径、查询参数或片段；跨域跳转时移除该标头。不使用浏览器登录 Cookie。

需要支持受控 Referer 的宿主；旧宿主会拒绝 Referer 并报 HEADERS_DENIED。同 ID 的新版 ZIP 请先停用插件，再通过插件卡片的「升级插件」上传，保留已有数据并重新确认权限。兼容检查、默认名称迁移及失败恢复规则见 [升级规范](../../../plugin/UPGRADES.md)。

公开页面接口不是官方稳定开放 API；格式变更时插件会报错，不承诺兼容所有腾讯文档类型。

## 构建与验证

运行 `./examples/plugins/tencent-docs-public/build.ps1`，生成 `artifacts/plugins/tencent-docs-public-windows-x64-0.2.0.zip` 及 SHA-256 校验文件。

- 插件测试：配置、真实正文快照解码、标题资源列表、首轮同步、未变化跳过、变化更新、全量同步、权限失败不推进游标。
- HTTP 通道测试：同源根 Referer、非法来源拒绝、跨域跳转移除，以及原有网络策略回归。
- Windows 原生测试 `TestTencentDocsNativeApproval`：真实 ZIP、未授权拒绝、授权后健康运行；用户提供的 RAG 文档标题和正文、首次输出 1 篇、再次同步输出 0 篇均已验证。

原生测试在临时安装目录中进行，不修改腾讯文档内容。Windows WFP 审计配置读取仍受账户权限限制；宿主 HTTP 请求审计正常，不能等同于完整系统级逐次网络审计。
